模块 3

Pack EoL deep case 一页综合

3.1 稳定边界：我们研究什么

Included

  • Production level：Battery Pack manufacturing
  • Primary process：Pack End-of-Line testing
  • Manipulated object：测试连接器及柔性线束
  • Robot task：定位/抓持或支撑 → 对准 → 接触插入 → 确认 → 安全拔出 → 归位
  • Decision：专用自动化、固定工业机器人、移动双臂/人形架构在何种条件下值得采用或继续评价

Outside / Adjacent

  • DCR：相邻任务，未证明同一工位、connector 或 robot
  • Tester：执行电气/功能测试，不是机器人物理操作本体
  • PLC/Safety：负责许可、互锁与安全停机
  • MES：负责 Pack、配方与结果关联
  • CATL 现场具体节拍、成本、成功率、安全状态机：仍为 UNKNOWN

3.2 任务不是一个动作，而是一个受状态门控的闭环

Pack 定位与识别
→ PLC 给出 safe-to-connect
→ Robot 完成 locate / grasp / align / insert / lock / confirm
→ PLC 允许 Tester 执行 EoL
→ Tester 完成测试并去能量
→ PLC 给出 safe-to-disconnect
→ Robot unlock / extract / return harness
→ MES 关联结果并放行或返修

这是由工序基线、工业方案、企业披露与系统工程推理组成的 reference abstraction，不是 CATL 现场逐帧复原。

3.4 三类架构的条件性综合

Architecture A
Dedicated automation

优先条件：C1 低多样性、C3 高产量/高节拍、C4 低频换型、C5 单工位、接口可机械标准化。

价值机制：用固定夹具、导向和可重复定位绕过部分 R1/R2 感知与控制复杂度。

边界：一旦 R4 变化需要频繁硬件改造，优势可能下降。具体设备是否具备力/电气确认取决于配置，不能一概写成“没有传感器”。

Architecture B
Fixed industrial robot

优先条件：C1 中等多样性、C4 日/班次级换型、C5 单工位，且 R1/R2/R5 需要视觉、力控与可编程动作。

价值机制：以可编程运动、传感器与工业控制接口覆盖变化和接触插接。

边界：C5 多工位或 C6 brownfield 时可能需要多台设备、围护和改造；“能覆盖”不等于总成本合理。

Architecture C
Humanoid / mobile dual-arm

优先评价条件：C1 高多样性、C4 高频换型、C5 多工位、C6 人类导向既有布局，并且移动/双臂能力确实被任务使用。

潜在价值机制：跨站复用、双臂线束支撑、复用既有工具和空间。

关键门：目标配置的 R3 工业安全集成、C10 成本与长期可靠性仍缺直接证据，所以只能写“值得评价”，不能写“部署就绪”或“更优”。

Pack EoL deep-case 的阶段答案：架构选择由两类因素共同决定——R1–R6 决定系统必须具备什么，C1–C10 决定这些能力在具体产线中是否值得以某种架构实现。Dedicated、fixed robot 与 mobile dual-arm 不是从差到好的序列，而是不同标准化程度、柔性需求、工位结构和证据成熟度下的条件选择。

模块 4 — 核心产出

Task–Requirement–Capability–Suitability Framework v0.1

下面七步是 Week 06 从一个案例中抽出的可复用方法。每一步都有输入、关键问题、输出和停止条件。以后换到 cell loading、inspection 或 multi-station handling 时，不是复制 Pack EoL 的答案，而是重复这七步。

F0
Scope & Evidence Contract｜先签范围与证据合同
输入：导师方向、生产层级、候选案例。
问：cell/module/pack？主工序？直接工业锚点？证据类型允许支持什么？
输出：Case Charter + evidence labels + excluded topics。
停止：没有明确 battery-manufacturing task 或机器人决策时，不继续做架构排名。
F1
Manufacturing-task Identification｜识别真正的制造任务
问：对象是什么？起点/终点是什么？任务为什么存在？完成判据是什么？失败后果是什么？
输出：一句任务定义：Actor manipulates object from state A to state B so that process X can occur.
停止：如果只能说“这里用了机器人”，说明任务尚未定义。
F2
Task Anatomy & Responsibility｜拆动作，也拆系统责任
问：自由空间、接触、确认、释放分别有哪些 sub-steps？Robot、process equipment、PLC/safety、MES、fixture 各负责什么？
输出：task cycle + responsibility map + 3–5 个关键 failure modes。
停止：如果 Robot 与工艺设备责任混淆，后续 capability mapping 无效。
F3
Requirement Extraction｜从每个动作推出要求
句法：Evidence → why it matters → effect on robot task → required capability → unknown。
输出：Requirement → Robot-task effect → Capability 表，并标 Generic / Hybrid / Battery-specific。
停止：“更灵活、更智能、精度更高”如果没有对应动作和物理机制，不算 requirement。
F4
Existing Baseline & Candidate Architectures｜先找现实基线
问：人工、专机、固定机器人、移动系统现在怎样完成同一功能？是否为同工序、邻近任务还是跨行业能力证据？
输出：baseline cards + transfer limits。
停止：没有 baseline 时不能声称新架构“更好”，因为比较对象不存在。
F5
Capability Mapping｜技术上能否覆盖关键要求
问：每种具体配置如何满足每个 requirement？依靠机械约束、感知、控制、工具、双臂、移动还是系统接口？
输出：SUPPORTED / CONDITIONAL / NOT SUPPORTED BY CURRENT EVIDENCE / UNKNOWN。
停止：不要数绿色格子；关键 safety gate 未满足可否定整体部署。
F6
Conditional Suitability｜把能力放回生产条件
问：产品多样性、节拍、换型、工位数量、brownfield、质量机制、扩展性与成熟度如何改变价值？
输出：scenario-based conditional conclusions。
停止：若结论中没有 condition，就只是技术简介，不是适用性评价。
F7
Evidence-bounded Decision & Transfer｜做阶段决定，再迁移
问：哪些结论是直接支持，哪些需缩小主张？关键 unknown 能用文献、设备资料、专家、scenario 或可选实验怎样降低？
输出：CONTINUE / NARROW / FUTURE SCENARIO / TRANSFER READY + next single case。
停止：不能因资料少就宣布 research gap，也不能因一个案例不成熟就推翻整条论文路线。

框架的“双门 + 两个闸”

门 1：Task Gate

机器人是否承担明确动作，battery requirement 是否改变它？

门 2：Condition Gate

即使能做，这个产量、换型与工位结构下是否合理？

闸 1：Safety Gate

硬性安全/合规要求若未满足，其他优势不能补偿。

闸 2：Evidence Gate

证据强度是否足以支撑主张；不足则降级结论，不虚构数据。

方法贡献为何不是“普通列表”：它规定了分析顺序、字段、证据标签、判断语言和停止条件。不同案例按照同一程序分析后，才可以做 cross-case comparison；否则只是把三个故事放在一起。

模块 5

完整示范：把 R3 与生产条件同时写进结论

你在 Day 4 的一句话回答只覆盖了“固定工位 + 高节拍 + 低换型 → dedicated”。方向正确，但漏了 task requirement 和另外两类架构。下面示范如何写成 thesis-ready conditional argument。

六段式结论模板
[生产条件 C] + [关键任务要求 R] + [候选架构] + [作用机制] + [证据] + [边界/UNKNOWN]

Scenario A

C1 低多样性 + C3 高节拍 + C5 单工位时，如果 connector/adapter 能固定且 R1/R2 的变化可由机械导向吸收，dedicated automation 可能更合理，因为设备商已经公开自动接触方案；但换型时间、传感器配置和经济性仍需具体设备数据。

Scenario B

C1 中等多样性 + C4 日/班次换型 + C5 单工位时，若 R1/R2/R5 要求在线视觉、力控与连接确认，fixed industrial robot 值得优先评价，因为邻近工业案例与论文支持这些能力；但目标 EoL connector 的 transfer validity 仍需核查。

Scenario C

C1 高多样性 + C5 多工位 + C6 brownfield时，mobile dual-arm/humanoid 因移动与双臂能力值得评价；但只要目标配置的 R3 安全握手和 C10 长期成熟度仍为 UNKNOWN，就不能从“值得评价”升级为“可部署或最优”。

为什么这三句话比“谁更灵活”强

  1. 每句话都先给工厂条件，而不是先选机器人。
  2. 每句话都说明能力如何作用于具体 requirement。
  3. 每句话都同时给出支持证据与不可外推边界。
  4. 结论可以随场景改变，因此不是品牌排名。
不能这样写：“Humanoid 在 C5/C6 更灵活，因此未来成长空间很大。”前半句仍需证明移动/双臂能力在目标任务中真的被使用；后半句没有可测量证据。可改为：“当 C5/C6 成为主导条件时，移动双臂的系统级价值值得评价，但其安全集成、可靠性和成本证据尚不足。”

模块 6

论文结论的证据语法

6.1 四种判断状态必须绑定“具体 claim”

状态真正含义可以怎样写不能怎样写
SUPPORTED当前证据直接或充分支持这个具体配置在该维度具备能力“该工业案例支持固定机器人完成视觉引导的柔性 connector handling。”“所有固定机器人都能稳定完成 Pack EoL。”
CONDITIONAL能力依赖额外配置、假设或尚未验证的 transfer“若增加 F/T sensing 且目标 connector 的力范围相容，则该方案值得试验。”“理论上能加传感器，所以已经可用。”
NOT SUPPORTED BY CURRENT EVIDENCE现有证据不足以支撑当前主张；不自动等于物理上做不到“现有来源不支持该 humanoid 已完成经验证的 R3 安全集成。”“没有公开 R3，所以 humanoid 不可能做到。”
UNKNOWN当前资料没有回答，且方向无法可靠判断“目标现场的 PLC safety handshake implementation 为 UNKNOWN。”“UNKNOWN 说明这里存在 research gap。”

6.2 “物理不成立”需要更强证明

只有当已定义配置缺少不可替代能力、且没有其他机制绕过该要求时，才能说它在当前假设下物理/系统上不成立。例如：

较强但合格的否定

若方案被严格定义为“无在线感知、无接触反馈、仅执行 pre-taught pose”，而连接器初始位姿变化超过被动导向可吸收范围，则该配置无法可靠完成 R2；这里的否定来自机制冲突。

不合格的泛化否定

“Pneumatic / dedicated automation 不够智能，所以不能做。”专机可能通过导向、夹具、传感器或 adapter 绕开问题；必须先定义具体配置。

6.3 证据类型各自能做什么

证据本案例中可以支持不能独立支持
DIRECT COMPANY DISCLOSURE企业声称在 Pack EoL/DCR 使用机器人处理柔性线束和连接器独立成功率、长期可靠性、成本优势、技术优越性
INDUSTRIAL BASELINEPack EoL 自动接触方案确实存在；固定机器人柔性 connector handling 确实存在CATL 现场使用同一结构、同一 connector 或同一安全状态机
PEER-REVIEWED PAPERDLO、位姿误差、接触插入、双臂操作的能力与局限将实验室性能数字直接复制到 Pack EoL 或“小墨”
ENGINEERING INFERENCE把分散证据组合成透明的 reference architecture 与 scenario hypothesis冒充已观察现场事实
UNKNOWN指示下一步最有价值的证据问题自动构成 research gap 或否定可行性
合格 claim = 对象与场景 + 作用机制 + 证据身份 + 适用边界 + 未知项

模块 7

哪些字段可迁移，哪些只属于 Pack EoL

“可迁移”不是把 R1–R6 原封不动复制到别的任务。真正可迁移的是分析问题与证据结构；具体 requirement 必须从新任务重新推出。

层级可迁移到其他案例的内容Pack EoL 专属或需重新验证的内容
Scope明确 production level、process、object、task start/end、comparison baselinePack EoL、DCR adjacent、测试 connector 与 harness
Task拆自由空间、接触、确认、释放；画责任泳道I1–I10 插接链、safe-to-disconnect
Requirement用 evidence → effect → capability → unknown 生成要求R1 柔性线束、R2 connector insertion、R3 HV interface 等具体内容

Condition产品多样性、节拍、换型、工位、brownfield、安全、质量、扩展性、成熟度connector variety、线束复杂度与测试站具体布局
EvidenceDIRECT / INDUSTRY / PAPER / INFERENCE / UNKNOWN 与 claim-level status具体来源的 transfer limit 和 CATL 现场未知
DecisionCONTINUE / NARROW / FUTURE SCENARIO / TRANSFER READYHumanoid 在 R3/C10 上的当前判断
迁移原则：保留问题，不保留答案。下一个案例仍问“对象、动作、要求、基线、能力、条件、证据”，但不能预先假设它也有线束、HVIL、接触插入或相同的三类架构结论。

DEEP CASE CONTINUES

Pack EoL connector handling 具有明确 battery-manufacturing task、robot actor、现实 baselines、可分析要求和实施问题，足以继续作为 deep reference case。

NARROW CLAIM

结论收缩为“架构的条件性适用性与值得评价的场景”。不主张小墨性能被独立验证，也不主张 humanoid 优于 fixed robot 或 dedicated automation。

FRAMEWORK TRANSFER READY

七步框架已经能对 Candidate A 提出结构化问题。Week 07 可以用一个相邻案例检验迁移性，而不是继续无限加深 Pack connector 细节。

Humanoid 在当前结论中的准确位置

不是：已证明更优的目标方案。

也不是：因为证据弱就被排除的“不行方案”。

而是：在高变型、多工位、brownfield 条件下值得评价的 prospective architecture；其 R3 安全集成、目标任务性能、长期可靠性和 C10 经济性需要进一步证据。在这些关键项解决前，不可写成 deployment-ready。

Framework v0.1 的实施评价不要求本周得到全部数字。它要求先说明：需要什么证据、哪些输入仍缺失、在缺失时结论必须怎样降级。

Week 07 single entry

只迁移到 Candidate A，先锁 task destination/interface，不并行打开 C。

你可以这样向 Thomas 汇报

1. Selection logic：I used Pack EoL connector handling as a deep reference case because it has a concrete battery-manufacturing task, direct industrial disclosure, established automation baselines and analyzable robotics requirements.

2. Task understanding：The robot does not perform the electrical test; it establishes and removes the physical test connection under PLC/safety permission.

3. Method：I decomposed the task, derived six requirement groups, mapped them to capabilities, and assessed three architectures under explicit production conditions.

4. Conditional result：Dedicated automation may fit stable high-volume interfaces; fixed robots may fit variable but stationary work; mobile dual-arm systems become worth evaluating for multi-station brownfield scenarios, but safety integration and maturity remain unresolved.

5. Next step：I will test whether the same method transfers to cell recognition, grasping and loading, beginning with the task boundary and battery-specific effects rather than with humanoid attributes.

不要在组会上说：“我已经证明 humanoid 最适合 Pack EoL”或“R3 没有资料，所以 humanoid 不适用”。准确说法是：当前证据使 humanoid/mobile dual-arm 成为某些场景下的 prospective option，但关键安全、成熟度与经济性项仍待验证。
